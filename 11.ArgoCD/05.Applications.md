### Goals
- The trainee will understand the Application resource and every important field in it
- The trainee will know how to deploy plain manifests, Helm charts and Kustomize with ArgoCD
- The trainee will understand the different sync policies and sync options

### Tasks
- Read about the Application resource and explain the following fields:
  - `spec.project`
  - `spec.source` - `repoURL`, `targetRevision`, `path` / `chart`
  - `spec.source.helm` - `valueFiles`, `values` / `valuesObject`, `parameters`, `releaseName`
  - `spec.sources` (multiple sources) - when would you need it? (hint: a chart from a Helm repo with a values file from your Git repo)
  - `spec.destination`
  - `spec.syncPolicy`
- How does ArgoCD decide whether a `path` is plain YAML, Helm or Kustomize?
- Explain the sync policies:
  - Manual sync vs automated sync
  - `prune` - what happens to a resource that was deleted from Git, with and without it?
  - `selfHeal` - what happens when someone runs `kubectl edit` on a managed resource, with and without it?
- Explain the following `syncOptions`: `CreateNamespace=true`, `ServerSideApply=true`, `PruneLast=true`, `ApplyOutOfSyncOnly=true`
- What is `ignoreDifferences`? Give an example where you need it (hint: an HPA changes `spec.replicas`)
- What does the `resources-finalizer.argocd.argoproj.io` finalizer do? What happens when you delete an Application with and without it?
- What does **Refresh** do? What does **Hard Refresh** do? How are they different from **Sync**?
- How does a rollback work in ArgoCD? Why is it disabled when auto-sync is on? What is the "GitOps way" to roll back?
- How does ArgoCD know which resources belong to which Application? (Read about the tracking label / annotation)
