### Goals
- The trainee will understand how ArgoCD orders the resources it applies during a sync
- The trainee will know how to use sync phases, hooks and sync waves
- The trainee will know how to order Applications relative to each other

### Tasks
- Read about sync phases and waves
- Explain the sync phases: `PreSync`, `Sync`, `PostSync`, `SyncFail` (and `PreDelete` / `PostDelete`)
- What is a **resource hook**? Which annotation turns a resource into a hook?
- Give a real use case for each phase (e.g. a DB migration Job, a smoke test, a Slack notification on failure)
- Explain the hook delete policies: `HookSucceeded`, `HookFailed`, `BeforeHookCreation`. What happens if you run a hook Job twice without a delete policy?
- What is a **sync wave**? Which annotation sets it? What is the default wave? Can a wave be negative?
- Explain the full order ArgoCD uses to apply resources in a sync (phase, wave, kind, name)
- Before moving to the next wave, what does ArgoCD wait for?
- Ordering between **Applications** (e.g. in App of Apps):
  - Put sync waves on child Application resources. Does the root app wait for a child app to be **Healthy** before moving on?
  - Since ArgoCD 1.8 there is no built-in health check for the `Application` resource. What do you need to add to `argocd-cm` so waves between Applications work? Why was it removed?
  - Can sync waves order Applications generated by an ApplicationSet? What can you use instead?
- What happens to the next waves if a resource in wave 1 never becomes healthy?
